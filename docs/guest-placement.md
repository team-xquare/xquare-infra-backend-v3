# 게스트 노드 배치 미리보기

`LocalGuestPlacementApi.preview(query, scope)`는 서버 프로세스 내부에서만 사용하는 읽기 전용 API입니다. HTTP 경로를 추가하지 않으며 VMID, 자원 예약, 게스트를 생성하지 않습니다.

- `query`에는 팀 ID, 카탈로그 템플릿 별칭, 요청 코어 수·메모리 바이트·최종 디스크 바이트를 넣습니다. 세 수치는 모두 양수여야 합니다.
- `scope`는 서버가 팀 권한을 검사한 뒤 만드는 자료입니다. 요청 본문에서 역직렬화하지 않습니다. 팀의 승인된 프로필, 남은 할당량, 관측치에 아직 반영되지 않은 예약 합계를 담습니다. 없는 팀 범위·다른 팀·없는 템플릿·할당량 초과는 인벤토리를 조회하지 않고 `Unavailable`로 응답합니다.
- 프로필은 노드 별칭과 실제 노드명의 일대일 매핑, 대상 스토리지, 타입별 템플릿을 지정합니다. QEMU는 원본 노드·템플릿 VMID·검토된 원본 디스크 스토리지 집합, LXC는 운영자가 승인한 원본 노드와 `vztmpl` 볼륨을 사용합니다. QEMU는 전체 복제 기준으로 `scsi0`의 단일 `스토리지:base-VMID-disk-N,size=정수단위` 볼륨만 취급합니다(`file=` 접두어 허용). 크기는 양의 정수 K/M/G/T를 1024진 바이트로 환산합니다. 요청은 원본 논리 크기 이상이어야 하며 대상에는 예약을 제외하고 요청 크기 전체가 남아 있어야 합니다. 다른 슬롯, 누락·중복 크기, 오버플로, 호스트 장치 및 미지원 구성 키·디스크 옵션은 로컬·원격 모두 제외합니다. 추가로 허용하는 값은 `vmgenid`의 8-4-4-4-12 형식 UUID, `smbios1=uuid=<UUID>` 단독 값, `boot=order=scsi0`뿐입니다. API에 쓰는 `vmgenid` 생성·비활성 지시값 `1`·`0`, 추가 SMBIOS 속성, 다른 부팅 장치나 순서 목록은 지원하지 않습니다. `digest`는 40자리 16진수, `name`은 단일 DNS 레이블, `description`은 8192자 이하 문자열, `cores`·`sockets`는 양의 정수, `memory`는 16 이상 정수 MiB 문자열, `ostype`은 공개 스키마 열거값만 허용합니다. 이 검사는 템플릿 구성을 판별하는 것이며 게스트 내부 OS가 기동하는지 검사하지 않습니다. 연결 복제나 축소를 가정하지 않습니다. 원격 노드는 원본 스토리지가 양쪽에서 활성·공유일 때만 후보입니다. LXC는 해당 후보 노드에 승인한 볼륨이 조회되어야 합니다. 원본·후보 양쪽에서 원본 스토리지가 공유로 확인되지 않으면 승인된 원본 노드만 후보입니다. 서로 다른 로컬 스토리지에 같은 파일명이 있다는 사실만으로 내용이 같다고 판단하지 않습니다. 파일 체크섬을 검증하는 기능은 아닙니다.
- 승인된 온라인 노드 중에서만 고릅니다. 예약 합계는 팀별 별칭이 아니라 서버가 설정한 고정 `proxmox.cluster-id`로 구분합니다. 같은 물리 클러스터에 연결하는 모든 인스턴스는 같은 ID를 써야 하고, 서로 다른 클러스터는 ID를 공유하면 안 됩니다. 미설정 시 배치 조회를 거절합니다. CPU·메모리 예약 키는 `(클러스터, 실제 노드명)`, 디스크 예약 키는 `(클러스터, 스토리지, 로컬 노드명 또는 공유 시 null)`입니다. 별칭은 응답과 동점 비교에만 사용합니다. CPU는 현재 사용 비율에 요청·예약 코어 비율을 더하고, 메모리는 현재 사용량·요청·예약의 합을 총량으로 나눕니다. CPU·메모리·디스크의 여유가 모두 있는 노드 중 `0.4 × 예상 CPU 비율 + 0.6 × 예상 메모리 비율`이 낮은 노드를 우선하며, 동점은 별칭 오름차순입니다.
- 성공은 `Selected(노드 별칭)`, 선택 불가·판단 불가는 `Unavailable`입니다. PVE 자격 증명·원본 구성·타 팀 식별자·업스트림 오류 본문은 반환하지 않습니다. 인벤토리 신선도는 조회 시작 시점부터 30초 이내인지 검사합니다. 이는 PVE 내부 수집기의 개별 지표 시각을 검증한다는 뜻이 아닙니다.
- 예약 장부와 동시 생성 트랜잭션은 아직 없습니다. 결과는 예약이 아니며 실제 생성 시 권한·할당량·템플릿·용량을 다시 검증하고 원자적으로 예약해야 합니다. 이 증분은 생성이나 디스크·백업 쓰기에 연결하지 않습니다.

계약 기준: [Proxmox 공식 API Viewer](https://pve.proxmox.com/pve-docs/api-viewer/)의 `GET /nodes`, `GET /nodes/{node}/storage`, `GET /nodes/{node}/qemu/{vmid}/config?current=1`, `GET /nodes/{node}/storage/{storage}/content?content=vztmpl`. 합성 단일 디스크 예시는 [upstream qm import가 메타데이터와 부팅 순서를 기록하는 코드](https://github.com/proxmox/qemu-server/blob/65f679cd2c77a7be50cc872ab5e25fcdbd795754/src/PVE/CLI/qm.pm#L935-L961)를 참고했습니다. 설치판 9.2.6에서 검증한 결과는 아닙니다.
